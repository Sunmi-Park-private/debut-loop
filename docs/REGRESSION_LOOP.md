# 회귀 루프 (스토리 엔진) 설계 — 본 게임

> 대상: `debut-loop`. 데모 = **1회차(사고) + 2회차(트루) 완주**, 30~40분.
> 상위 스펙: `아이돌게임_통합안1_스펙_v0.2.md` §6-1 · 연계: `CARD_SYSTEM.md`
> 아키텍처 원칙: data(JSON) → engine(순수 TS) → ui(Pixi)

---

## 0. 확정 결정 (Director 승인)
- **훅 유지**: 프롤로그에서 데뷔 사고 공개 → "데뷔 때 사고난다, 어떻게 막나". (진범 은폐/축 이동 **안 함**)
- **1회차**: 당한다 — 단서 **관찰만(포착 불가)** → 5막 사고 → **회귀(강제)**
- **2회차**: 추적한다 — **회귀 가속** + 단서 **능동 포착** → 진범(정 실장) 규명 → 5막 저지 → **데뷔 성공(트루) 무조건**
- 데모 목표 30~40분.

---

## 1. 상태 (State 확장)
```ts
type LoopCount = 1 | 2;
interface State {
  // ...기존(gauges, flags, clues, deck 등)
  loopCount: LoopCount;        // 현재 회차
  seenBeats: Set<BeatId>;      // 회귀 가속용 — 이전 회차에 본 비트
}
```

## 2. Beat 회차 필터 (라우터)
```ts
interface Beat {
  // ...기존
  loop?: LoopCount;   // 없으면 공통(양 회차 등장), 있으면 해당 회차만
}
// 라우터: b.loop 가 없거나 == state.loopCount 인 비트만 후보
```
- **공통 비트**(loop 없음): 규합·성장·기시감 등 뼈대 (양 회차)
- **1회차 전용**(`loop:1`): 단서 "관찰"(못 잡는 버전), 사고 결말
- **2회차 전용**(`loop:2`): 단서 "능동 포착", 진범 규명, 저지·트루

## 3. 회귀 가속 (2회차)
```
loopCount==2 && seenBeats.has(b.id)  → 빠른 넘김(자동 진행/축약 카드)
새 비트(loop:2, 미열람)              → 정독
```
→ 2회차는 "아는 내용 스킵 + 새 단서 집중"으로 체감 시간 단축.

## 4. 결말 고정 (분기 아님)
```
1회차 5막: 단서 능동 포착 경로 없음(loop:1) → 사고 비트 → triggerRegression()
   triggerRegression(): loopCount = 2; cursor = 프롤로그 직후; seenBeats += 지나온 비트; 덱/기시감 일부 계승
2회차 5막: 단서 4개 포착(loop:2) → 저지 성공 → 트루엔딩 (무조건)
```
- 1회차는 **반드시** 사고→회귀 (단서 포착 비트가 loop:2에만 존재하므로 구조적으로 보장).
- 2회차는 **반드시** 트루 (저지 조건이 2회차 경로에 배치).

## 5. 계승 (회귀 시 유지/리셋)
| 요소 | 회귀 시 |
|------|---------|
| 기시감 플래그(memory_*) | **계승**(파편 기억 누적 = 서사) |
| 단서(clue_*) | 리셋 → 2회차에 다시 포착 |
| 덱(카드) | 일부 계승(로그라이크 성장감) — 범위는 튜닝 |
| 게이지 | 리셋(초기값) |
| seenBeats | 유지(가속용) |

## 6. 흐름
```
[1회차] 프롤로그(사고 공개) → 규합 → 성장 → 단서 관찰(못 잡음)
        → 5막 데뷔: 사고 재현 → 회귀
[2회차] 가속 재생(본 카드 빠르게) → 단서 능동 포착 → 진범 규명
        → 5막 데뷔: 저지 성공 → 데뷔 성공(트루) → 데모 종료
```

## 7. 우선순위 & 구현 순서
> 카드 시스템(`CARD_SYSTEM.md §7`)과 **독립 트랙**. 병행 가능.

| 순위 | 단계 | DoD |
|:--:|------|-----|
| 1 | `loopCount`/`seenBeats` 상태 + 라우터 `loop` 필터 | 유닛테스트: 회차별 비트 노출 정확 |
| 2 | `triggerRegression()` + 결말 고정(1회차 사고/2회차 트루) | 1회차 완주→회귀→2회차 트루 시뮬 통과 |
| 3 | 회귀 가속 UI(seen 빠른 넘김) | 2회차 체감 시간 단축 확인 |

## 8. 열린 결정 (튜닝)
1. 덱 계승 범위(전부/일부/없음)
2. 회귀 가속 방식(완전 자동 스킵 vs 빠른 수동 넘김)
3. 3회차+ 확장(본선) — 데모는 2회차까지
4. 기시감 계승이 2회차 단서 포착에 주는 보너스 여부
