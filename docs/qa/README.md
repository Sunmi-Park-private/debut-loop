# QA 진행 안내

> debut-loop QA 피드백을 처리하는 방법. 팀 3명(개발 1, 영상 디자이너 2) 기준.
> 작성일 2026-08-06

---

## 저장소가 두 개인 이유

| 저장소 | 공개 | 무엇이 있나 |
|---|---|---|
| `debut-loop` | **공개** | 게임 코드, 에셋, PR |
| `debut-loop-qa` | **비공개** | **QA 이슈, 진행 보드** |

사전과제 심사 요건상 코드 저장소는 공개여야 합니다. 하지만 QA 과정(미완성 자산 현황, 내부 코멘트, Fail 기록)까지 심사위원에게 보일 필요는 없어서 이슈만 비공개 저장소로 분리했습니다.

**디자이너 두 분은 `debut-loop-qa`에서만 활동하시면 됩니다.**

## 디자이너용 — 하는 일

### 1. 구글시트에 QA 결과 기록 (지금까지와 동일)

[QA 체크리스트 시트](https://docs.google.com/spreadsheets/d/1MLN_JtoLJQ-QhGz1avhDDBOP0aSU240D_Z-4qXA9gI8/edit)

- `판정` 열에 `Pass` / `Fail` / `N-A` / `?` 입력
- 오른쪽 코멘트 열에 자유롭게 의견 작성

**이슈로 등록되는 것:**

| 판정 | 코멘트 | 등록? |
|---|---|---|
| Fail | 있든 없든 | ✅ 버그로 |
| ? | 있든 없든 | ✅ 질문으로 |
| N-A / Pass | 있음 | ✅ 개선 요청으로 |
| Pass | 없음 | ❌ |
| 빈칸 | — | ❌ (미검수로 간주) |

### ⚠️ 검수는 반드시 20:9 비율에서

**크롬 창을 대충 세로로 줄여서 보면 실기에 없는 문제가 보입니다.**

게임 아트는 요즘 폰 비율인 **20:9 (1080×2400)** 기준으로 제작됐습니다. 크롬 창을 임의 크기로 줄이면 그보다 짧고 넓은 비율이 되어, 실제 폰에서는 멀쩡한 화면이 잘려 보입니다.

실제로 QA #10(타이틀 상단 잘림)이 이 경우였습니다:

| 환경 | 비율 | 상단 잘림 |
|---|---|---|
| 크롬 창 430×800 | 0.537 | **78px** |
| iPhone 15 | 0.461 | 12px |
| **Pixel 7 · 갤럭시 (20:9)** | **0.450** | **0px** |

#### 올바른 검수 방법

크롬 **개발자도구의 기기 시뮬레이션**을 쓰세요. 창 크기를 손으로 맞추지 마세요.

1. 게임 화면에서 `F12` (맥은 `⌥⌘I`) → 개발자도구 열기
2. 왼쪽 위 **기기 아이콘** 클릭 (`⇧⌘M`)
3. 상단 드롭다운에서 기기 선택 — **Pixel 7** 또는 **Galaxy S20 Ultra** 권장
4. 이 상태로 검수 진행

여러 기기에서 다르게 보이는 것 같으면, 이슈에 **어느 기기로 봤는지 꼭 적어주세요.** 그것만으로 원인이 절반은 좁혀집니다.

### ⚠️ 중요한 규칙 하나

**이슈로 등록된 뒤에는 그 행의 판정·코멘트를 고치지 마세요.**

시스템이 "판정 + 코멘트"로 중복 여부를 판단하기 때문에, 오타 하나만 고쳐도 같은 내용의 이슈가 하나 더 생깁니다.

- 내용을 보충하고 싶으면 → **시트가 아니라 GitHub 이슈에 코멘트**를 달아주세요
- 재검수해서 판정이 실제로 바뀐 경우는 → 고쳐도 됩니다. 새 이슈가 생기는 게 맞습니다

### 2. GitHub 이슈에서 결과 확인

수정이 끝나면 이슈에 이런 코멘트가 달립니다:

```
수정 완료했습니다.
- 변경: src/ui/uiSkin.ts — title-hero를 cover 모드로 전환
- PR: <링크>
- 수정 후 화면: <스크린샷 링크>

확인 부탁드립니다.
```

스크린샷을 보고 **괜찮으면 이슈를 닫아주시고**, 아직 이상하면 코멘트로 알려주세요.

### 3. 직접 이슈를 만들어도 됩니다

시트에 없는 문제를 발견하면 `debut-loop-qa`에서 바로 이슈를 만드셔도 됩니다. 이때 아래를 적어주시면 작업이 빨라집니다:

- **어느 화면**에서 (예: 로비 › 카드덱)
- **어떻게 들어가서** (예: 로비 하단 배너를 위로 스와이프)
- **무엇이 기대와 다른지** (예: 카드 뒷면이 보여야 하는데 앞면이 보임)
- 가능하면 **스크린샷**

## 개발자용 — 명령어

### `/qa-sync`

시트를 읽어 신규 피드백만 이슈로 등록합니다. 이미 등록된 건 자동으로 건너뜁니다.
생성 전에 목록을 보여주고 승인을 받습니다.

### `/qa-work`

이슈를 우선순위대로 한 건 가져와 수정하고, PR 직전까지 진행합니다.

**우선순위**: 플레이 영상에 잡히는 화면(프롤로그·로딩·타이틀·로비·스토리)의 버그 → 나머지 버그 → 개선 요청 → 질문

제출 순서상 자산 QA는 영상 촬영보다 먼저 끝나야 합니다. 영상에 폴백 화면이 잡히면 안 됩니다.

## 라벨

| 라벨 | 의미 |
|---|---|
| `qa` | QA에서 나온 이슈 (전부) |
| `bug` | 명확한 결함 (판정 Fail) |
| `enhancement` | 개선 요청 (판정 N-A/Pass + 의견) |
| `question` | 의도된 동작인지 확인 필요 (판정 ?) |
| `qa:code` | 소스 수정 필요 |
| `qa:asset` | 에디터 설정값(배율·좌표) 조정으로 해결 |
| `qa:question` | 코드 변경 없이 답변만 |

## 자동화되지 않는 것

- **시트 되쓰기** — 이슈 상태가 시트로 돌아가지 않습니다. 진행 현황은 GitHub에서 보세요
- **시트 하단의 행에 붙지 않은 메모** — 자동 추출이 안 됩니다. 직접 이슈로 등록해주세요
- **PR 머지** — 사람이 판단합니다
