> 대상: `debut-loop`. **제출물 ①=플레이 가능한 웹 빌드(GitHub Pages)**를 책임지는 로드맵.
> 연계 설계: `CARD_SYSTEM.md` · `REGRESSION_LOOP.md` · 레퍼런스/폴백: `mockup/mockup.html`
> 확정(Director): 본게임 Pixi 완성 · **수직 슬라이스** 진행 · 목업=폴백
> 아키텍처 원칙: data(JSON) → engine(순수 TS, 완료) → ui(Pixi)

## 0. 제출 요건 (NAN 2026 사전과제 ~8/10)
5종 모두 필수(누락 시 심사 제외):
1. **플레이 가능한 빌드 + 소스** — 웹(GitHub Pages 링크) 또는 APK + 전체 소스 ← **이 로드맵의 대상**
2. 플레이 동영상 30~60초 (YouTube)
3. 게임 소개·설명 (PDF)
4. AI 활용 기술 (PDF)
5. 팀원 롤 기술서 (PDF)

> 데모 = **1회차(사고) + 2회차(트루) 완주**, 목표 30~40분.

## 1. 아키텍처
- **얇은 Pixi 셸 + 순수 엔진 구독**: `ui/`는 `state`를 읽어 그리기만, 입력은 엔진 함수 호출(`applyEffect`·`advance`·`resolveTraining`·`resolveGate`)로 방출. UI에 게임 규칙 없음.
- **레이아웃**: 검증된 목업(파스텔 스탯패널·카드·대사창)을 레퍼런스로 재현.
- **데이터 주도**: `beats/demo2_zeroc.json`(loop 태그) · `cards.json` · `config.json`.
- 엔진 코어(회귀 루프·카드)는 **완료**(순수 TS + 유닛테스트 27개). UI·배선·데이터만 남음.

## 2. 수직 슬라이스 (각 단계 = 항상 플레이·제출 가능 상태)

| S | 관통 내용 | DoD | 재사용 |
|:--:|-----------|-----|--------|
| **S0** | Pixi 부트 + 1화면(스탯패널+카드+좌/우 선택) → 스와이프 → `applyEffect` → 게이지 반영 → 다음 비트 | 브라우저에서 비트 몇 장 스와이프로 진행됨 | router·state·gauges |
| **S1** | 주차/막 진행 + 엔딩(`advance`) + **회귀 1→2회차** + 가속(seen 빠른 넘김) + **드래그 스와이프**(목업 bindDrag 이식) | 1회차 사고→회귀→2회차 트루 완주 | progress |
| **S2** | 미니게임 3엔진(rps/stop/match) — 관문(막 통과) 배선 | 막 경계에서 관문 미니게임 동작 | 목업 로직 이식 |
| **S3** | 연습 메뉴 UI + **카드 획득**(`resolveTraining`) + 덱 표시 | 연습→카드 적립·멘탈 소모, 게이지 상승 없음 | training (**카드 2순위**) |
| **S4** | 관문 **카드 선택**(`gatePickCount`+`resolveGate`) 적용·소모 | 관문서 N장 선택→게이지 반영→덱 감소 | gate (**카드 3순위**) |
| **S5** | 파스텔 스킨 + 이미지 에셋 교체 + 폴리시(연출·전환) | 제출 품질 | 에셋 목록 |

> **S5 뼈대 완료(2026-07-24)**: 에셋 슬롯 파이프라인(`assets.json`+로더, 파일 드롭=자동 반영, idle 시퀀스 지원) · 배경+카드 초상+연습 스탠딩 적용 · 개발도구 dev 게이트(`?dev=1`). **잔여**: 디자이너 에셋 교체(진행 중), 연출 폴리시(전환·기시감 플래시), 제출 준비(레포·Pages·영상·PDF).

> **커밋/배포 주기**: debut-loop 자체 git 레포는 Director가 생성 예정 — 생성 전까지 슬라이스별 커밋·Pages 갱신은 보류, 코드·테스트만 진행.

> 원래 "카드 2·3순위 배선"은 S3·S4에서 UI와 함께 흡수. 순수 로직은 완료 상태라 **배선+렌더**만 남음.
> **각 슬라이스 종료 = 커밋 + GitHub Pages 갱신** → 언제 마감돼도 제출 가능.
