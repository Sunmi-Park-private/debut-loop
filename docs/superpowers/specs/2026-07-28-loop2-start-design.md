# 2회차 시작 개선 — 설계

- 날짜: 2026-07-28
- 상태: Director 승인 (구현 전)
- 대상: Debut Loop! (debut-loop)

## 문제

1회차 종료 후 회귀(2회차)에 들어가면 "회귀 가속"이 가속처럼 동작하지 않는다.

- 92개 비트 중 79개가 공통 비트라 2회차 대부분이 "▶▶ 기억 속 장면" 축약 카드로 나오는데, 텍스트는 40자에서 잘리고 회색이라 읽을 수 없으면서 **여전히 매 장 좌/우 선택을 해야 하고 효과도 그대로 적용**된다. 표시만 "빠르게 넘기기"이고 실제 조작량은 1회차와 동일하다.
- 2회차 오프닝이 1회차 오프닝("참사 → 되감기")의 축약 재생으로 시작해 서사가 꼬인다.

## 결정 사항 (Director 확정)

| 항목 | 결정 |
|---|---|
| 2회차 진행 방식 | **유저가 2회차 시작 시 선택**: ⚡ 빠른 모드 / 📖 정속 모드 |
| 빠른 모드 — seen 비트 | **탭 1회로 넘기기** (선택 버튼 제거) |
| 빠른 모드 — 게이지·효과 | **1회차와 동일하게** — 1회차 선택을 기록해 그대로 재적용 |
| 정속 모드 | 1회차와 완전히 동일 — seen 비트도 일반 카드, **좌/우 자유 선택**(분기 변경 가능) |
| act 관문 3개(리듬×2·슬롯) 반복 | **그대로 유지** (변경 없음) |
| 주간 연습 매주 등장 | **이번 범위 제외** (현행 유지) |
| 2회차 오프닝 | w0 참사·되감기 비트를 1회차 전용으로, 2회차 전용 오프닝 비트 추가 |

## 설계

### A. 엔진 — 선택 기록·계승·재적용

- `State`에 `choices: Record<string, "left" | "right">` 추가 (`engine/types.ts`, `createState`에서 `{}` 초기화).
- `runController.choose(dir)`에서 `state.choices[current.id] = dir` 기록.
- `triggerRegression`에서 `next.choices = { ...state.choices }` 계승 (seenBeats와 동일 수명).
- 재적용 전용 로직은 만들지 않는다 — UI가 기록된 방향으로 기존 `choose(dir)`를 호출하므로 게이지·플래그·단서·포인트·후속 분기 조건이 1회차와 완전히 동일하게 재현된다.

### B0. UI — 2회차 모드 선택

- 회귀 엔딩 화면(`screens.ts`의 regress 이벤트)의 "계속" 단일 버튼을 **모드 선택 2버튼**으로 교체:
  - **⚡ 빠른 모드** — "이미 겪은 장면은 탭 한 번에 넘어가요" (본 설계의 탭 넘기기)
  - **📖 정속 모드** — "1회차처럼 모든 장면을 다시 보며 선택해요"
- 선택값은 `app.ts` 모듈 세션 상태(`loop2Mode: "fast" | "normal"`)로 유지 — 로비에 나갔다 와도 유지, 새 런(엔딩→재시작·치트 새 런) 시 초기화.
- 정속 모드에선 seen 여부를 무시하고 1회차와 동일하게 렌더 (축약 카드·replay 미사용). 새 선택은 choices에 덮어써 기록되지만 데모는 2회차가 마지막이라 영향 없음.
- 모드 중도 전환은 범위 밖 (기록만).

### B. UI — seen 카드의 탭 넘기기 (빠른 모드)

- `swipeCard.ts`: `CardOpts.replay?: "left" | "right"` 추가. replay가 지정되면:
  - 좌/우 버튼, 드래그 스와이프, ←/→ 방향키 스와이프를 렌더/배선하지 않음.
  - 카드 전체가 탭 타깃, 하단에 `[탭하여 넘기기]` 표시.
  - "그때의 선택 — {선택 라벨}" 한 줄 표시 (게이지 변동의 근거 노출; 기존 nextBump 델타 팝업 유지).
  - 키보드 Space/→ 는 탭과 동일하게 진행.
- `app.ts` `draw()`: `loop2Mode === "fast" && c.seen && c.state.choices[c.current.id]` 이면 replay 모드로 렌더, 탭 시 기록된 방향으로 `choose()`.
  - **기록 없는 seen 비트는 일반 선택 카드로 폴백** (안전망).
- 빠른 모드의 첫 seen 카드에서 튜토리얼 가이드 1회: "이미 겪은 장면은 탭 한 번에 지나가. 🆕 새로운 장면에서 단서를 찾아!"

### C. 데이터 — 2회차 오프닝 (`src/data/beats/demo2_zeroc.json`)

- `d2_w0_disaster`, `d2_w0_rewind` → `loop: 1` 지정.
  - 안전 확인 완료: 두 비트 효과는 없음/`rewound` 플래그뿐이며, `rewound`를 requires로 쓰는 비트는 0개.
- loop:2 전용 오프닝 비트 1개를 `d2_w0_rewind` 다음 위치에 추가 (week 0, act 0, 효과 없음, 좌/우는 톤 선택). 문구 초안: "다시 기획사 문 앞. 이번엔 전부 선명하다 — 붉은 섬광, 꺼진 마이크, 그리고 누군가의 그림자. 이번엔 범인을 찾는다." (구현 시 다듬어 Director 확인)
- `d2_w0_staff_intro`는 공통 유지 — 선택별 플래그(trust_staff)가 있으므로 탭 재적용으로 1회차 선택을 재현.

### D. 테스트 (vitest)

- choose 시 선택 기록됨.
- triggerRegression 후 choices 계승, 기록된 방향 재적용 시 게이지/플래그가 1회차와 동일.
- 기록 없는 seen 비트 폴백 (choices에 없으면 replay 미지정).
- 기존 76개 테스트 회귀 없음.

### 검증

- `tsc --noEmit` + vitest 전체.
- dev 서버 수동 확인: 1회차 완주 → 회귀 → 모드 선택 화면 → (빠른) 2회차 오프닝 → seen 카드 탭 진행 → 새 비트(단서)에서 정상 카드 / (정속) seen 비트가 일반 카드로 자유 선택.
- 빌드(APK·단일 HTML)는 Director 요청 시에만.

## 범위 밖 (기록만)

- 2회차 진행 중 모드 전환(☰ 메뉴 토글 등) — 플레이 후 필요하면 추가.
