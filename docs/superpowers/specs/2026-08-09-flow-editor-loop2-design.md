# 게임 플로우 에디터 — 2회차 대사 편집 설계

> 작성일 2026-08-09 · 대상 브랜치 `fix/audition-feature`

## 문제

2회차 회상 카드의 문구를 어디서도 고칠 수 없다. 에디터에 칸이 없어서가 아니라,
**편집할 데이터가 존재하지 않기 때문이다.**

비트 95개 중 77개가 "공통" — 1회차와 2회차 양쪽에 나온다. 2회차에서 이 비트들은
`seen` 축약 카드로 표시되는데, 문구를 코드가 그 자리에서 만들어 낸다.

```ts
// swipeCard.ts
text: seen && raw.length > 40 ? raw.slice(0, 40) + "…" : raw,
```

40자에서 기계적으로 자르므로 문장이 중간에서 끊긴다. `loop: 2` 전용 비트 11개는
별도 비트라 지금도 편집되지만, 나머지 77개는 손댈 방법이 없다.

## 목표

- 공통 비트마다 2회차에서 보일 문구를 직접 쓸 수 있다
- 쓰지 않은 비트도 어색하지 않게 나온다
- 2회차 흐름을 통으로 읽으며 작업한다
- 1회차 대사를 실수로 건드리지 않는다

## 데이터

`Beat`에 회상 전용 필드를 하나 붙인다. 모든 항목이 선택적이라 기존 95개 비트는
그대로 둔다.

```ts
export interface BeatRecall {
  textKey?: string;
  leftLabel?: string;
  rightLabel?: string;
}

export interface Beat {
  // ...기존 그대로
  recall?: BeatRecall;
}
```

`replay`가 아니라 `recall`인 것은 `swipeCard`에 이미 `replay?: "left" | "right"`
(그때 고른 방향)가 있어서다. 같은 이름을 쓰면 읽는 사람이 둘을 혼동한다.

## 렌더

2회차 회상 카드가 값을 고르는 규칙:

| 자리 | 값 |
|---|---|
| 본문 | `beat.recall?.textKey` → 없으면 `beat.textKey` |
| 좌 라벨 | `beat.recall?.leftLabel` → 없으면 `beat.left.label` |
| 우 라벨 | `beat.recall?.rightLabel` → 없으면 `beat.right.label` |

빈 문자열은 "지정 안 함"으로 다룬다. 그러지 않으면 칸을 비우는 순간 대사가
사라진다.

**40자 축약은 제거한다.** 폴백이 전문이므로 자를 이유가 없고, 이것이 문장이
중간에 끊기던 원인이다. 카드 높이는 이미 본문 줄 수를 따라 늘어나므로 긴 회상
대사도 잘리지 않는다.

## 에디터 — 탭

상단에 `1회차` | `2회차` 탭. 각 탭은 그 회차에 실제로 플레이되는 비트만 순서대로
보여준다.

| 탭 | 조건 | 개수 |
|---|---|---|
| 1회차 | `loop !== 2` | 84 |
| 2회차 | `loop !== 1` | 88 |

2회차 탭의 노드에는 종류를 배지로 구분한다 — 공통 비트는 `↩︎ 회상`,
`loop: 2` 비트는 기존 `2회차` 배지.

탭 전환 시 선택 비트가 새 목록에 없으면 선택을 해제한다.

## 에디터 — 편집 패널

2회차 탭에서 **공통 비트**를 고르면 회상 편집 칸 세 개가 뜬다. 각 칸 위에 1회차
원문을 읽기 전용으로 깐다.

```
◀ 1회차 원문   무너지는 무대. 아무도 우리를 보지 않았다.   ← 회색·비활성
  2회차 대사   [                                      ]   ← 여기만 입력
               1회차와 동일 — 비워두면 위 문장이 그대로 나옴
```

잠금 장치는 두지 않는다. 위는 못 고치는 원문, 아래는 쓰는 칸 — 위치만으로
구분된다. 잠금 UI는 앞서 한 번 혼란을 만든 적이 있다.

`loop: 2` 전용 비트는 회상이 아니라 새 장면이므로 지금과 같은 전체 편집 패널이
뜬다.

## 에디터 — 중복 표시

**회상 칸이 비어 1회차를 그대로 물려받는 칸은 프레임을 색으로 강조**하고
`1회차와 동일` 배지를 단다. 값을 쓰면 강조가 풀린다.

타임라인 노드에도 같은 표시를 얹어, 88개 중 아직 손대지 않은 비트가 어디인지
스캔만으로 보이게 한다.

## 라이브 프리뷰

기존 `sendPreview()` 경로에 `recall`을 실어 보낸다. 오버레이 병합과 `beats-preview`
푸시는 그대로 쓴다. 저장 없이, 리로드 없이, 진행 상태를 유지한 채 반영되는 지금
동작이 회상 대사에도 같이 적용된다.

## 저장·검증

`/__beats` 저장은 비트 객체를 통째로 직렬화하므로 필드 추가만으로 동작한다.
빈 문자열만 담긴 `recall`은 저장 시 통째로 제거해 파일에 잡음이 남지 않게 한다.

플로우 에디터의 기존 검증에 한 줄 추가 — `recall`이 있으면 세 항목 모두
문자열이거나 없어야 한다.

## 테스트

폴백 규칙을 순수 함수로 빼고 유닛 테스트를 붙인다.

```ts
export function recallOf(beat: Beat): { text: string; left: string; right: string }
```

- 값이 있으면 그 값
- 없으면 1회차 값
- 빈 문자열이면 1회차 값 (지정 안 함으로 취급)
- 축약이 일어나지 않는다 (40자 넘는 대사가 그대로)

에디터 쪽은 탭 필터가 순수 계산이므로 `beatsOfLoop(beats, 1 | 2)`로 빼서 테스트한다.

## 경계

- 1회차 렌더는 바뀌지 않는다 — `recall`은 `seen` 카드에서만 읽는다
- 선택지의 효과(effects)는 회차별로 나누지 않는다. 회상에서 다시 고르는 것이
  아니라 그때의 선택을 되짚는 화면이라, 효과가 갈라질 이유가 없다
- 기존 layout.json 좌표는 그대로다. 컴포넌트 구성이 바뀌지 않는다
