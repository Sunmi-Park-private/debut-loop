# 오디션 멤버 영입·교체 시스템 — 설계

- 날짜: 2026-07-28 (v2: 2026-07-29 맹점 검토 7건 반영 · v3: 2026-07-29 코드 대조 최종 검토 5건 반영)
- 상태: Director 승인 — 구현 착수
- 대상: Debut Loop! (debut-loop)

## 목적

카드덱에서 오디션 카드를 모아 오디션 진행권을 얻고, 오디션으로 신규 멤버를 영입하며, 기량(status)이 낮은 멤버를 교체해 최종 5인을 확정하는 시스템. 스토리 자동 합류를 2명(유월·보라)으로 줄이고 나머지는 오디션으로 채운다.

## 결정 사항 (Director 확정)

| 항목 | 결정 |
|---|---|
| 스토리 자동 합류 | **유월(W1) + 보라(W3)** 만. 시안·하리는 오디션 후보 풀로 이동 |
| 도입 시점 | **D안: 각 막의 📷 이벤트 비트 직후 윈도우 (W3 평가 · W7 평가 · W12 밈전 · W17 직캠) + W18 "데뷔조 확정"에서 최종 락인** |
| 교체 범위 | **Phase 1: 오디션 슬롯 2개 간에만 교체 가능** (하루·유월·보라 고정). 유월·보라 교체는 Phase 2+ — 이름 하드코딩 비트 ~18개 토큰화 + 단서1(보라 스케줄) 대체 서사가 필요해 범위 분리 |
| 후보 풀 | 시안 + 하리 + **임시 후보 2명(가칭 "리안"·"다온" — 이름·콘셉트는 Director 확정 전 임시, 실루엣 표시)**. 방출된 후보는 풀로 복귀 |
| 일정 | Phase 1(시스템+핵심 토큰화) 먼저, Phase 2(후보 콘텐츠 완성·유월/보라 교체)는 후속 |

## A. 멤버 모델

```ts
// State에 추가
interface MemberSlot { characterId: string; role: RoleId; stat: number; joinedWeek: number }
members: MemberSlot[]; // 최대 5 — [0]=하루 고정
membersLocked: boolean; // W18 락인 후 true
```

- 하루: 게임 시작 시 stat 65. 유월 W1 합류 stat 70, 보라 W3 합류 stat 60(각성 `member_awakened` 시 +20)
- 오디션 영입자: 오디션 미니게임 성적 → perfect 80 / good 65 / clear 50 (±5 랜덤 시드)
- **기량 변동 소스** (⚠️ 월말평가 비트는 텍스트 연출뿐, 실제 미니게임 배선 없음 — 검토로 확인): **막 관문(리듬·슬롯·격자) 성적으로 전원 변동** perfect +5 / good +2 / clear −3, 보조로 주간 연습 perfect 시 +1
- 회귀 시: members는 리셋(1회차와 동일 시작). 오디션 카드는 기존 계승 규칙(cardCarryOver, 앞에서부터 N장)을 따르므로 계승 보장 없음 — 멤버 점검 보드에 안내 문구

## B. 오디션권 순환

- 연습 "오디션 대비" → 오디션 카드 획득 (기존)
- **오디션 카드 3장 → "오디션 진행권" 교환** — tickets.json의 기존 `audition` 티켓 재활용(cost 4→3 조정), 멤버 점검 보드에서 교환 버튼
- **⚠️ 수급 산술 보정** (검토 반영): 오디션 카드는 주 1회 연습에서만 획득 가능 → 4장 기준이면 W3 첫 윈도우에서 개최가 산술적으로 불가능. 보정 2종:
  1. **W1 스토리 지급 비트 신규**: 정 실장이 진행권 1장을 잡아온다("첫 오디션은 내가 준비했어" — 은인 연출과 정합, `grantTickets:["audition"]`) → W3 첫 윈도우에서 1회 개최 보장
  2. 교환 요구치 4→3장으로 완화
- 진행권은 `state.deck`(티켓)에 보관, 윈도우에서만 사용 가능. 오디션 카드는 관문 게이지 카드와 **이중 용도**(교환하면 관문에서 못 씀) — 교환 확인 문구에 명시

## C. 멤버 점검 보드 (신규 UI)

- **열리는 시점**: 각 막 📷 이벤트 비트 직후 — **W3 월말평가 · W7 월말평가 · W12 밈전 · W17 직캠** (검토 반영: 월말평가는 W3·W7뿐이므로 "막별 📷 이벤트"로 트리거 정의) — 주간 연습 보드와 같은 패턴의 전면 보드. draw 우선순위: 자유연습 > 멤버 보드 > 주간연습 > 관문 > 비트
- 구성: 슬롯 5개(초상+이름+role+기량 막대) · 후보 풀 리스트(방출자 복귀 포함) · 오디션 카드 보유 수 · [오디션 카드 3장 → 진행권 교환] · [🎤 오디션 개최(진행권 1장 소모)]
- **오디션 개최**: **리듬게임 엔진 재사용** (Director 지시 2026-07-29 — 연습 '오디션 대비'=rps와 자연 차별화) → 성적 → 후보 1명 등장(풀에서 랜덤, 기량=성적 기반) → [영입/보류]. **보류 후보는 보드의 멤버 목록 하위 섹션에 기량과 함께 표시되어 언제든(윈도우에서) [영입] 또는 [버리기] 가능** (Director 지시 2026-07-29). 버리기 = 이번 회차 풀·자동충원 제외(`State.droppedCandidates`), 회귀 시 복귀
- **교체 (Phase 1)**: 오디션 슬롯 2개 간에만 — 만석이면 영입 시 기존 오디션 멤버 중 방출 대상 선택, 방출자는 풀로 복귀. 하루·유월·보라는 고정(교체 버튼 비활성 + "데뷔조 핵심 멤버" 표시)
- W18 도달 시: 빈 슬롯은 잔여 후보 중 최고 기량 자동 충원 + `membersLocked=true` + 보드에 "데뷔조 확정" 표시, 이후 윈도우 미오픈

## D. 스토리 개편 (Phase 1 범위)

1. 시안(d2_w2_cyan)·하리(d2_w2_hari) 합류 비트 **삭제**
2. 시안·하리 이름이 박힌 비트를 role 토큰으로 치환 + `requires.castRoles` 부여:
   - 시안 계열(helper2 role): w5_cyan_online, w8_cyan_guard, w11_cyan_rap, w13_clue3/obs3(로그 분석), w13_cyan_reveal(전 안티 반전 — **영입 시 캐릭터 플래그 `cast_cyan`을 세우고 `requires.flags:["cast_cyan"]`로 시안 영입 런에서만 노출**, castRoles는 캐릭터 식별 불가하므로), w21_team_join(**시안+유월 동시 언급 — {helper2} 토큰화 + 미캐스팅용 유월 단독 문구 분기**)
   - 하리 계열(mentor role): w2_hari→삭제, w6_hari_tip, w10_hari_warn, w14_hari_save, w19_hari_probe, w21_hari_dig, w22_clue4(증거)
   - 캐스팅 치환은 기존 `{antiStaff}` 토큰 메커니즘 재사용 — 영입 시 `state.casting[role] = characterId` + 캐릭터 플래그(`cast_<id>`) 기록, 이름 토큰 `{helper2}`/`{mentor}` 렌더
3. 단서 비트(clue3·clue4)는 미영입 시에도 스토리가 막히면 안 됨 → 역할 미캐스팅 시 대체 비트 추가 (단서 획득 경로 보존): **단서3 = 하루·유월이 직접 로그 분석, 단서4 = 루나(팬)의 제보**
   - **배타 처리** (v3 확정): 영입 시 `cast_role_<role>` 플래그를 함께 세우고, 대체 비트에 `notFlags:["cast_role_helper2"(또는 mentor), "clue_*"]` — 미영입 런에서만 대체 경로가 열림(영입 런에서 단서를 오답으로 놓치면 기존처럼 놓친 것) — 엔진 무변경
4. W4 "5인 완성" 비트 → "팀의 뼈대가 모였다 — 남은 자리는 오디션으로" 톤 수정, 첫 팀 사진 비트도 인원 무관 문구로
