## 4. 우리 프로젝트 준비 상태 (2026-08-05 실측)

> 이 절부터는 주최 측 원문이 아니라, 현재 `debut-loop` 프로젝트를 실제로 점검한 결과입니다.

### 4-1. 🔴 즉시 해결이 필요한 것

| 항목 | 현재 상태 | 왜 문제인가 | 해야 할 일 |
|---|---|---|---|
| **git 저장소** | `debut-loop`은 **독립 저장소가 아니며 어떤 저장소에도 추적되지 않음**. 상위 `~/GitHub`(다른 프로젝트)의 작업 트리 안에 untracked 상태로 존재 | 제출 요건 1의 **"전체 소스 코드 + 커밋 기록 유지"**를 충족할 수 없음. 지금 저장소를 새로 만들면 커밋이 1개뿐인 상태로 제출됨 | `debut-loop`에서 `git init` → GitHub 저장소 생성 → 초기 커밋. 이후 작업은 의미 단위로 커밋해 기록을 쌓기 |
| **웹 배포** | GitHub Pages 워크플로 없음 | 제출 형태 중 가장 확실한 경로(링크 클릭 즉시 플레이)가 비어 있음 | 저장소 생성 후 Pages 배포 워크플로 추가 (`npm run build` → `dist` 배포). Vite `base` 경로 설정 필요 |

### 4-2. 🟡 준비돼 있으나 확인이 필요한 것

| 항목 | 현재 상태 | 확인할 것 |
|---|---|---|
| **APK 빌드** | `.github/workflows/android-apk.yml` 작성 완료 (수동 실행, debug 빌드, 아티팩트 `debut-loop-debug-apk`) | 저장소 생성 후 실제로 1회 돌려서 APK가 나오는지. debug 빌드로 제출 가능한지(설치 시 "출처를 알 수 없는 앱" 경고) |
| **단일 HTML 빌드** | `dist-single/` 산출물 존재 | 파일 하나로 플레이 가능한지 — 심사자 배포 대안으로 쓸 수 있음 |
| **외부 에셋 라이선스** | 이미지·영상·BGM 다수 사용 중 | 2-4 문서에 출처·라이선스를 전부 적으려면 **에셋 출처 목록을 지금부터 정리**해야 함 (생성 AI 산출물이면 사용한 도구·모델명 기재) |
| **자산 적용 상태** | UI 슬롯 141개 중 23개, 배경 17개 중 7개, 캐릭터 스킨 121개 중 75개 미업로드 | `docs/QA-ASSET-CHECKLIST.md`로 검수. 영상 촬영 전에 최소한 **영상에 잡히는 화면**은 폴백이 노출되지 않아야 함 |

### 4-3. 🟢 문서 작성 시 활용할 기존 자료

| 제출물 | 활용 가능한 기존 문서 |
|---|---|
| 게임 소개 및 설명 문서 | `docs/BUILD_ROADMAP.md`, `docs/CARD_SYSTEM.md`, `docs/REGRESSION_LOOP.md`, `docs/PLAN_S0~S4.md`, `docs/PLAN_TUTORIAL.md` |

## 5. 제출 순서 권장안

의존 관계상 아래 순서로 진행해야 뒤에서 다시 손대는 일이 없습니다.

1. **저장소 생성 + 커밋 기록 시작** — 이후 모든 작업이 기록으로 남음
2. **자산 QA** (`docs/QA-ASSET-CHECKLIST.md`) — 영상에 폴백 화면이 잡히지 않게
3. **웹 배포(GitHub Pages) + APK 빌드** — 플레이 링크 확보
4. **플레이 동영상 촬영·업로드** — 배포된 빌드로 촬영해야 실제 제출물과 일치
5. **게임 소개 및 설명 문서 PDF** — 3번의 링크, 4번의 영상 링크가 들어감
6. **AI 활용 기술 문서 PDF** — 에셋 출처 목록 포함
7. **팀원 롤 기술서 PDF** — 2인 이상일 때만
8. **최종 점검** — 링크 4종(저장소·Pages·APK·YouTube)을 시크릿 창에서 열어 접근 가능 확인
